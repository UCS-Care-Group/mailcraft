- Automatic Replies for IMAP accounts whose server keeps Sieve scripts (ManageSieve: Dovecot, Cyrus, Stalwart and many hosters) ([#9999](https://github.com/GITHUB_REPOSITORY/issues/9999)). File › Info › Automatic Replies turns them on or off, with a reply inside your organisation (your address's domain) and one outside, and a time range where the server can test dates. They are kept in a script of MailCraft's own, `mailcraft`, so they go out while MailCraft is closed. MailCraft never writes over a script it didn't write and never switches off a script of yours: a script changed elsewhere is left alone until you choose Replace with MailCraft's. The Sieve server is the IMAP server on port 4190 with STARTTLS, or the one you name in Account Settings. When the Sieve server can't be had, File › Info, the dialog and Rules and Alerts say what was found there, naming the host and port: nothing answers; it says nothing (a port that expects encryption from the start, as Dovecot's `ssl = yes` on the sieve listener, which ManageSieve doesn't use, is named as such); something else answers; no STARTTLS (MailCraft then doesn't sign in); or the secure connection failed. Try again asks once more.
- Rules kept on the server for IMAP accounts whose server keeps Sieve scripts ([#9999](https://github.com/GITHUB_REPOSITORY/issues/9999)), as for Microsoft accounts: a rule goes into MailCraft's script, after the Automatic Replies, when Sieve can do all of it (words and addresses of the sender and recipients, words in the subject or body, mail to you, size; move, copy, delete, mark as read, flag, clear the flag, stop processing), and then runs while MailCraft is closed. Any other rule stays on this computer, and Rules and Alerts says which part keeps it there. Your own active script is never switched off, and a script changed elsewhere is left alone until you choose Replace with MailCraft's.
- Rules and Alerts also lists the rules of a Sieve script of your own that your IMAP server runs, made in webmail or another program, as Outlook lists server rules made elsewhere ([#9999](https://github.com/GITHUB_REPOSITORY/issues/9999)). They are shown, never changed: MailCraft doesn't switch, move, delete or rewrite them, and what it can't describe is named by its Sieve command. File › Info says when that script sends your automatic replies. A rule kept in MailCraft's own script looks for the sender's and recipients' words in their addresses, as on Microsoft accounts.
- Change Rule in Rules and Alerts ([#9999](https://github.com/GITHUB_REPOSITORY/issues/9999)): the pencil beside a rule, or a double click on it, opens the rule builder filled in with the rule, and Save changes it in place, keeping its place in the order and whether it is switched on. A rule kept in an IMAP account's Sieve script is written there again; a rule a Microsoft account's server keeps can't be changed yet (the pencil says so), and the rules of a Sieve script of your own are never changed.
- Rules and Alerts shows the rules of your own Sieve script more fully ([#9999](https://github.com/GITHUB_REPOSITORY/issues/9999)): tests on a message header line (as words in the message header, an exact one as exactly), any of several such tests, and the names your webmail gave the rules (Roundcube's `# rule:[…]`, RainLoop's and SnappyMail's filter names), with a rule your webmail switched off shown off. They are still shown only, never changed.
- Sieve rules for IMAP accounts whose server keeps Sieve scripts ([#9999](https://github.com/GITHUB_REPOSITORY/issues/9999)): a rule written in Sieve itself, for what the rule builder can't say, kept in MailCraft's script on the server in its place among your rules and run there. It is checked before it is kept, and a mistake is shown with its line and column. Rules and Alerts lists it by its name as a Sieve rule; you can switch it on and off, move and delete it there, and its editor comes in a later version. An agent that wants to make one that can redirect, reply, reject or notify asks you as for sending mail.
