- On Linux and the BSDs, an attachment opens only when it is of a kind the desktop knows by name (documents, pictures, sound and video, archives, mail, calendars, cards, signatures and keys) and the desktop agrees the file is that kind; MailCraft asks it with gio or kmimetypefinder, and says so when neither is installed. Any other attachment can be saved with Save As ([GHSA-2669-rh8f-mcw8](https://github.com/GITHUB_REPOSITORY/security/advisories/GHSA-2669-rh8f-mcw8)).
- In the Flatpak build, an attachment of a kind whose name stands for more than one kind of file (such as PNG pictures, JSON, Ogg audio, Markdown and web pages), or of a picture kind older computers don't know yet (AVIF, HEIC, JPEG XL), isn't opened from MailCraft; save it with Save As and open it yourself ([GHSA-2669-rh8f-mcw8](https://github.com/GITHUB_REPOSITORY/security/advisories/GHSA-2669-rh8f-mcw8)).
- Markdown files, and keys, certificates and signatures (.asc, .gpg, .pem, .p7m, .p12, .pfx, .key, .crl and the like), are asked about before they open, as web pages and Office files with macros are; on Android, files that are asked about first are no longer offered to Share from the message ([GHSA-2669-rh8f-mcw8](https://github.com/GITHUB_REPOSITORY/security/advisories/GHSA-2669-rh8f-mcw8)).
