- One message that can't be downloaded no longer stops the rest of Send/Receive. After a connection error on a message, MailCraft opens a fresh connection and carries on with the next message and the folders after it; a message that fails in three runs in a row is left out and said so, in File › Info too, where Try again takes it up again, and a connection that fails again on the next message ends the run as before. A record that fails its check in the middle of an encrypted connection now says in plain words that antivirus or firewall software that scans mail connections is the usual cause ([#1581](https://github.com/GITHUB_REPOSITORY/issues/1581)).
