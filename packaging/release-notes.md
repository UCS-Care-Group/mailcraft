**MailCraft 0.12.0 in short**: new features and fixes for the public beta (testers welcome; sign up in [#11](https://github.com/GITHUB_REPOSITORY/issues/11))
- S/MIME and OpenPGP: signed mail is checked in the reading pane, and your own certificates and keys, and other people's Public keys, are managed in File › Options › Security ([#30](https://github.com/GITHUB_REPOSITORY/issues/30)).
- Import a .pst File brings in calendar items, tasks, notes and journal entries, and large distribution lists ([#815](https://github.com/GITHUB_REPOSITORY/issues/815)).
- Gmail's categories (Primary, Social, Promotions, Updates, Forums) as folders or tabs ([#911](https://github.com/GITHUB_REPOSITORY/issues/911)).
- Help › Report a Problem sends a report straight to the team, no GitHub account needed ([#956](https://github.com/GITHUB_REPOSITORY/issues/956)).
- Account colours, automatic bulleted and numbered lists, pictures kept in replies and forwards, and attachment previews (off by default).
- Faster: Empty Folder on a huge folder takes about a second ([#1037](https://github.com/GITHUB_REPOSITORY/issues/1037)).
- And more fixes, listed below.

**What's new**
- Enable attachment previews in File › Options to preview PDFs and supported images in the reading pane with local PdfCraft or PhotoCraft. [#1053](https://github.com/UCS-Care-Group/mailcraft/issues/1053)
- Import a .pst File now brings in notes and journal entries too, and mail kept as rich text keeps its HTML. The import is no longer a preview. Notes and the journal have no window of their own yet ([#815](https://github.com/GITHUB_REPOSITORY/issues/815)).
- OpenPGP Digital signatures are now checked in the reading pane; Public keys can be imported, listed and removed ([#30](https://github.com/GITHUB_REPOSITORY/issues/30)).
- File › Options › Security lists your own certificates and keys and imports a `.p12` or an OpenPGP secret key; the Public keys kept for other people are listed and removed there, an OpenPGP key is marked as verified after comparing its fingerprint, and a contact's card shows its certificates ([#30](https://github.com/GITHUB_REPOSITORY/issues/30)).
- Help › Report a Problem can now send a report straight to the MailCraft team, no GitHub account needed: press Send report, and the window shows the report's reference. Only what the window shows goes, and only when you press Send; the report is kept private unless the team makes a real problem public on GitHub, where you can choose to be mentioned by your GitHub username. Open on GitHub is still there ([#956](https://github.com/GITHUB_REPOSITORY/issues/956)).
- Import a .pst File now brings in calendar items, with their repeat patterns and time zones, and tasks. Nothing is sent to anybody ([#815](https://github.com/GITHUB_REPOSITORY/issues/815)).
- Typing `* ` or `- ` at the start of a line in a message now starts a bulleted list, and `1. ` or `1) ` a numbered one. Undo straight afterwards puts back what you typed, and File › Options › Mail › Automatic bulleted and numbered lists turns it off ([#973](https://github.com/GITHUB_REPOSITORY/issues/973)).
- An S/MIME Digitally signed message says what checking its signature found, in a bar above it: verified, signed but the signer not verified, changed after it was signed, or can't be checked (an algorithm that's no longer safe, for one), with Details of who signed and their certificate; its row in the list wears a seal of the same. Trust comes from the certification authorities your system trusts for mail (on Linux its mail bundle, on Windows the roots trusted for secure mail; none on FreeBSD, whose authorities are for web sites, and none yet on macOS). An opaque signed message shows what it holds, its attachments too; revocation isn't checked yet ([#30](https://github.com/GITHUB_REPOSITORY/issues/30)).
- A contact's S/MIME certificates and OpenPGP keys in a vCard (`KEY`) are kept when the card is imported and written back when contacts are exported ([#30](https://github.com/GITHUB_REPOSITORY/issues/30)).
- A Gmail account's Inbox shows Gmail's categories, Primary, Social, Promotions, Updates and Forums, as five folders under it, each with its unread count, whether the account signs in with Google or an app password. Account Settings can hide them, or keep desktop alerts to mail in Primary, and the search finds them with `gmail:social` and the rest ([#911](https://github.com/GITHUB_REPOSITORY/issues/911)).
- View › Gmail Categories can show them as a row of tabs above the Inbox instead, each with its unread count ([#911](https://github.com/GITHUB_REPOSITORY/issues/911)).
- **Pictures in all mail from the message.** The bar above a message whose pictures were not downloaded now also offers **Download pictures in all mail**, the switch from File › Options in one click. It first says what that means: every sender's server learns when you opened a message and from which internet address. It stays off until you say yes, mail in Junk E-mail still never downloads pictures by itself, and File › Options turns it off again. ([#910](https://github.com/GITHUB_REPOSITORY/issues/910))
- Each account can have a colour (Account Settings › Colour; a new account is given one): a dot beside its name in the folder pane, and a stripe on its mail in a search of All Mailboxes, so that whose mail is whose is seen at a glance ([#893](https://github.com/GITHUB_REPOSITORY/issues/893)).
- Import a .pst File brings in the members of a large distribution list too: past about 15,000 bytes Outlook keeps them in a form of their own, which the import now reads, up to 1,000 members a list ([#843](https://github.com/GITHUB_REPOSITORY/issues/843)).
- **Pictures in replies and forwards.** When you reply to or forward a message whose pictures are written into it rather than attached, the pictures now stay in the original below your text and go with your message, as they do from Outlook. Only pictures MailCraft would show are carried, within the same limits on size and number; nothing is downloaded for them ([#602](https://github.com/GITHUB_REPOSITORY/issues/602)).

**Fixes**
- A message an earlier version left in the Outbox from a draft begun on another device, and that a run then held, goes again with Send Again (Microsoft and Exchange server accounts; [#738](https://github.com/GITHUB_REPOSITORY/issues/738)).
- A folder that a Microsoft 365 or Exchange server keeps for itself, such as RSS Feeds, can no longer end up in Deleted Items here while the server still has it where it was: once the server says it is one of its own, the folder goes back where the server has it, you are told why, and Delete Folder, Rename and Move are greyed out for it from then on (and refused with the reason when an agent or a script asks). A move or deletion the server turns down for another reason puts the folder back too, rather than stopping Send/Receive on it every time ([#1069](https://github.com/GITHUB_REPOSITORY/issues/1069)).
- An imported `.ics` file no longer hides in your Microsoft 365 calendar without reaching it: when the account's calendar was the only one, an imported appointment went into it as if it were there, was never sent, and nothing offered to send it. It now goes into the calendar **On this computer**, with the bar above the calendar and **Move to Calendar** in its menu offering to move it to your account's calendar; one that an earlier import left behind goes there at the next Send/Receive ([#1050](https://github.com/GITHUB_REPOSITORY/issues/1050)).
- Empty Folder on a folder of many thousands of messages no longer leaves the window not responding: a folder of 200,000 now empties in about a second (it took about an hour), and Delete, Delete Permanently, Archive and Junk of a large selection are as quick. Undo works as it did, and the server is told the same as before ([#1037](https://github.com/GITHUB_REPOSITORY/issues/1037)).
- A server that can't be reached because it shares no encryption with MailCraft (often an old Exchange 2010 offering only CBC cipher suites) now says so, and that its administrator can turn on the AES-GCM suites, instead of a general connection failure ([#977](https://github.com/GITHUB_REPOSITORY/issues/977)).
- Add Account recognises legacy Outlook.com custom domains from their Hotmail MX records and selects Microsoft sign-in instead of guessed IMAP and SMTP settings; owners can keep their custom-domain address after confirming that Microsoft's returned address is an alias of the same mailbox ([#1070](https://github.com/UCS-Care-Group/mailcraft/pull/1070)).
- Connecting Outlook's Favorites for an account whose organisation requires administrator approval for reading mailbox settings now shows the administrator approval message once instead of repeatedly prompting to connect ([#986](https://github.com/GITHUB_REPOSITORY/issues/986)).
- Week numbers in the calendar line up: in the Month view and in the date navigator every digit has a place of one width, where a number such as 20 used to start left of the others ([#1009](https://github.com/GITHUB_REPOSITORY/issues/1009)).
- Import a .pst File no longer brings mail kept only as rich text in with an empty body: its text is the body, and the rich text is kept as an attachment ([#815](https://github.com/GITHUB_REPOSITORY/issues/815)).
- HTML newsletters keep headings up to 48 pixels, inline line height, image spacing, and the width of centered tables that size to their contents. CSS table rows and cells use the same layout as HTML table tags ([#1021](https://github.com/GITHUB_REPOSITORY/issues/1021)).
- The Flatpak uses installed host fonts for Japanese and other scripts, and links in the reading pane are underlined close to their text ([#1016](https://github.com/UCS-Care-Group/mailcraft/issues/1016)).
- An IMAP account with more than 2,000 folders has them all read now, up to 10,000 in one Send/Receive, each in its place in the folder tree, and the folder pane shows every folder of an account (it showed at most 4,000); with more than that, the message says how many were left out and the first of them ([#991](https://github.com/GITHUB_REPOSITORY/issues/991)).
- In English, dates now follow your system's regional format: in the UK, Ireland, Australia, New Zealand, India, South Africa and elsewhere outside the US, Canada and the Philippines they are written day first (`14/10/2026`, `14 Oct 2026`), and the clock and the first day of the week are the region's unless you chose your own in File › Options. On Linux and FreeBSD the format is read from `LC_TIME` ([#978](https://github.com/GITHUB_REPOSITORY/issues/978)).
- An Exchange server account no longer downloads every message in full: like a Microsoft account, it keeps mail in full only within its Mail to keep offline (12 months unless you change it in File › Info or Account Settings), and older mail as headers and a preview that download when you open them. "Messages to download per folder" in File › Options is for IMAP accounts ([#966](https://github.com/GITHUB_REPOSITORY/issues/966)).
- A digitally signed (S/MIME or OpenPGP) message moved or copied to another IMAP account, saved as an `.eml` file or forwarded as an attachment now carries its signed body exactly as it arrived, so its signature still checks there; signed and encrypted mail is kept as it came for checking in a later version ([#30](https://github.com/GITHUB_REPOSITORY/issues/30)).
- In a plain-text message, Font, Font Size, Font Color and Text Highlight Color are greyed with the other formatting buttons, and say why ([#862](https://github.com/GITHUB_REPOSITORY/issues/862)).
- The reasons why your automatic replies weren't changed, and why desktop alerts can't be shown, are now translated on their own, apart from the heading they follow, so a translator writes each heading once ([#912](https://github.com/GITHUB_REPOSITORY/issues/912)).
- Text in Calibri, Cambria and other fonts that carry small bitmaps beside their outlines is drawn whole again: since 0.11.0 most of its letters were missing, drawn in white ([#889](https://github.com/GITHUB_REPOSITORY/issues/889)).
- The Reminders window answers Dismiss, Dismiss All, Snooze and its close button while the main window is minimized ([#771](https://github.com/GITHUB_REPOSITORY/issues/771)).
- Sign-in and server errors of IMAP and SMTP accounts are shown in the interface's language in Send/Receive problems, the status bar and Add Account, not only in English; what a server says for itself is still shown as the server wrote it ([#872](https://github.com/GITHUB_REPOSITORY/issues/872)).

**Public beta.** For Microsoft accounts (personal, or work or school) MailCraft is a working mail, calendar and contacts program, kept in step with Outlook on the web; keep Outlook to hand while you try it, and tell us in an issue if anything is lost or out of step. Much of what a daily mail program needs is still to come, and other kinds of account are welcome but not part of the beta. What works is in the [README](https://github.com/GITHUB_REPOSITORY#what-works-today).

MailCraft for Windows, macOS, Linux, FreeBSD and the web. Every file is listed with its SHA-256 in `SHA256SUMS.txt`.

| Platform | File | |
|---|---|---|
| Windows 10/11 (x64, x86, ARM64) | `mailcraft-<ver>-windows-<arch>.msi` | Installer for all users: Program Files\MailCraft and the Start menu; offers MailCraft for `mailto:` links and for `.eml`, `.ics` and `.vcf` files without taking them over (choose it in Settings › Default apps); uninstall from Installed apps. `mailcraft-cli.exe` is installed next to the app. |
| | `mailcraft-<ver>-windows-<arch>-portable.zip` | Portable: unzip anywhere and run `mailcraft.exe`; includes `mailcraft-cli.exe`. Registers nothing. |
| macOS 11+ (Apple silicon and Intel) | `mailcraft-<ver>-macos-universal.dmg` | Drag MailCraft to Applications. |
| | `mailcraft-cli-<ver>-macos-universal.zip` | The command-line tool and MCP server alone. |
| Linux x86_64 and aarch64 (glibc 2.35+) | `mailcraft-<ver>-linux-<arch>.AppImage` | `chmod +x` and run (if it does not start, add `--appimage-extract-and-run`). The `.zsync` next to it enables delta updates. |
| | `mailcraft-<ver>-linux-<arch>.deb` / `.rpm` | `sudo apt install ./mailcraft-*.deb` or `sudo dnf install ./mailcraft-*.rpm`. |
| | `mailcraft-<ver>-linux-<arch>.flatpak` | `flatpak install --user mailcraft-*.flatpak` (the freedesktop runtime comes from Flathub). |
| | `mailcraft-<ver>-linux-<arch>.tar.gz` | `bin/mailcraft`, `bin/mailcraft-cli`, the desktop entry, metainfo and icons under `share/`. |
| FreeBSD 15 (x86_64) | `mailcraft-<ver>-freebsd-x86_64.tar.gz` | The two programs, the desktop entry and the icons. |
| Any modern browser | `mailcraft-web-<ver>.zip` | The app as a static site (WebAssembly). From a browser it reaches JMAP servers only, to read ([docs/jmap.md](https://github.com/GITHUB_REPOSITORY/blob/main/docs/jmap.md)): bring other mail in with File › Import. |

MailCraft keeps your mailbox in its settings folder and saves as you go; one window per mailbox. With a Microsoft 365 or Outlook.com account you sign in on Microsoft's page, and the sign-in is kept by the system's credential store (Windows, macOS, and the Secret Service of GNOME Keyring or KWallet on Linux). What works, and how far each part is from Outlook, is in the [README](https://github.com/GITHUB_REPOSITORY#what-works-today) and in `docs/gaps.md`.

The builds are not signed with a publisher certificate yet: Windows SmartScreen and macOS Gatekeeper will ask before running them.
