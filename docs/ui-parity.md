How the window compares with the target's. The look is the Craft apps' own (WordCraft's design
tokens, type rungs and ribbon widgets, with MailCraft's teal accent); the *arrangement* is the one
Outlook users know. No pixel of the target's artwork is used: every icon is drawn in code.

## The window

| Part | State | Notes |
|---|---|---|
| Title bar | yes | Quick Access (Send/Receive, Undo, Redo), search box with scope (each keyword the query language reads, `From:`, `Subject:`, drawn as a pill around the keyword and its colon, what follows it plain text), a Copy Diagnostics pill (D1) and a Report a Problem pill beside it (a GitHub issue started in the browser, or a message to the maintainers started in the composer; the owner sends it), account avatar. macOS integrated title bar. No customisation |
| Ribbon | yes | File, Home (changes with the module), Send / Receive, Folder, View, Help, and a Message tab while writing. Simplified (one row, what doesn't fit behind `…`; the default) or Classic (three rows), chosen in View › Layout (`ui.ribbonMode`). Collapsible by double-click. No keytips (Alt), no customisation |
| Icons | yes | Every icon drawn in code on a 20-unit grid in one stroke, fitted to the screen's pixels (sharp one-pixel lines at 20 pt and 100 %), with round ends and corners. Outlines by default; fills only for marks of a state (a flag, a star, unread, importance). Ink by default, the accent only on the part that is the action or the change (one "new" plus everywhere, an arrow that moves something); flag, star, tick and category colours are theme colours readable on every pane, and no two variants differ by colour alone. Shown at 12, 16, 20, 24 and 32 pt, with simpler drawings at 16 pt and below. Original drawings: nothing copied or traced from any vendor |
| Module bar | yes | Mail, Calendar, People, Tasks, with the Inbox's unread count. No Notes, no reordering |
| Folder pane | yes | Favorites, account trees, collapse/expand, unread counts, context menu, resizable. For an account that signs in with Microsoft the Favorites are the folders Outlook shows there, in Outlook's order, read from the server (never written: they are changed in Outlook); one quiet line under the heading offers to connect them, or says why they can't be had, and File › Options switches back to the favourites kept here. They are read through Microsoft Graph, for a work or school account as for any other; when an administrator has to approve it first, the pane says so and offers what can be done (a message to copy for the administrator, the page that says what to do next). No drag and drop, no search folders, no groups; a favourite that is a person, a category or a group is not shown. A shared mailbox has its own tree under its owner's, its unread counted on its own folders; its folders can be put among the Favorites, kept in MailCraft whatever the owner's come from, and are named there with the mailbox ("Inbox - support@…"). A folder among the Favorites whose name a folder of another of the owner's accounts has too (two Inboxes) is named there with its account ("Inbox - Work"), as on a row of a search of All Mailboxes. Outlook's own Favorites that point into a shared mailbox are not shown yet. The folder menus (Move to Folder, Copy to Folder, Move Folder, the message's Move) open with a search box that has the keyboard: typing narrows them to the folders whose name holds it, any part, ignoring case and accents, each shown with its place in the tree; the arrow keys and Enter choose, Escape clears the search and then closes the menu |
| Message list | yes | Laid out from the target's at 100 %, to the pixel ([the measurements](#the-message-list-measured)): a header with All and Unread as tabs and the arrangement (By Date) with the arrow that turns the list over; rows of the sender (11 pt), the subject with the time at the end of its line, and 0–3 lines of preview (8 pt); a line of dots round the row the keys act on; the bar an unread message wears; a scroll bar with arrows in its own lane. Date/sender/importance groups (View › Arrange By › Show in Groups turns the headings off, `view.groups`), a single-line layout (View › Message Preview › Single Line, `view.oneLine`: sender, subject, marks and time on one line, 32 px a row, both kept with the other options), arranged by size each message's size under the time (for one only partly here the size its server gave, when it gave one; #273), conversations as one row with a count, marks, category marks, flag and delete on the row under the pointer, the read switch down a row's left edge, dragging to a folder, context menu, multi-select with Ctrl/Shift, keyboard movement, virtualised. The preview is what the message says to its reader: the words of its HTML (the opening line a sender hid for message lists included), without markup, invisible padding or web addresses. A flagged message's row is tinted, and its text is red once its follow-up is past due; a completed flag is not tinted. No column view (Outlook's columns, to choose and sort by, are the follow-up to #214), no collapsing of groups, no opening a conversation in place; the tabs do not turn into a menu in a narrow list (the one in use stays, the others are in the arrangement's menu). Below a search that takes in a Microsoft account, More results on the server (greyed, Not connected, offline or without a sign-in); what it finds comes under On the server, with the folder it is in under the time in a search of All Mailboxes (as the local results show theirs), and opens into that folder |
| Reading pane | yes | Right, bottom or off; header with avatar, recipients, date; notes (flag, importance, replied, pictures withheld); attachment chips (double-click or Open opens one with the computer's own program for its kind, as Outlook does; programs, scripts, shortcuts, installers, disk images and files of no kind are refused and can be saved; Office files with macros and web pages are asked about first; in the browser, Open downloads; right-click for Save As and Remove); conversation jump list; formatted body with clickable links. Simplified HTML (gap #6); no zoom, no inline reply |
| Composer | yes | In place of the reading pane: From (several accounts), To, Cc, Bcc, Subject, attachment chips, body in rich text (bold, italic, underline, a size, links, bulleted and numbered lists eight levels deep, a font and a text colour, a signature's pictures; copy and paste as HTML on the desktop; the Message tab's Basic Text group and Ctrl+B/I/U/K/Z/Y while the body has the keyboard), the original of a reply shown as the reading pane shows it; Send, Attach, Save draft, Discard. Gap #7; no pop-out window |
| Calendar | yes | Side pane with a month navigator and calendar list; day, work-week, week and month grids; drag to move. A second time zone in the time bar. No schedule view, overlay, drag to resize or create |
| People | yes | List with letter headings and favourites; contact card with recent mail. No business-card or table views, no groups |
| Tasks | yes | Filters, quick add, grouped list with check boxes, details pane. No To-Do bar, no table view |
| Backstage (File) | yes | Info (accounts with Download messages in full and the Mail to keep offline slider, 3 days to All, which asks before a shorter window removes mail from this computer; mailbox, rules, categories), Open & Export, Options (general, mail, calendar), Signatures (the list, the composer's editor with Insert/Paste Picture and a picture's width, description and layout, Create from details, a preview as recipients see it and in plain text, each account's two defaults), About. No print, no automatic replies, no add-ins |
| Status bar | yes | Counts, messages from the last action, Send/Receive status (a click shows Send/Receive Progress), reading-pane switch. While a Send/Receive runs, a bar fills under a steady label (Updating the account, or Send/Receive) rather than naming each folder; what it came to and its problems are in words. Text that doesn't fit ends in an ellipsis, whole under the pointer. No zoom slider, no connection indicator |
| Send/Receive Progress | yes | A panel over the foot of the main window, not a window of its own: opened from the status bar's Send/Receive text, its red "Send/Receive problems" link (at the first problem) or Send / Receive › Show Progress, never by itself; Escape or a click elsewhere closes it. "Your organisation has to approve MailCraft first" is a page of its own, shown when the sign-in comes back saying so or from its link: why, and what to do next (an administrator approves on Microsoft's page, opened from there and waited for; anybody else copies a message for one; try again; not now, which leaves nothing behind). A sign-in that ends otherwise says how, in a sentence (the page came back with a no, nothing came back, no browser could be started), with Try again and the way to that page. An account that exists gets the same page as a dialog when a Send/Receive its owner asked for is refused for want of an approval. MailCraft has no web view: the provider's page is in the system's browser, never in this window |

## The message list, measured

Distances in pixels at 100 %, from the target's list in its dark theme beside ours (2026-10-12).
A row is measured from the hairline above it.

| What | Target | Ours |
|---|---|---|
| Hairline to the top of the sender's capitals | 15 clear | 15 |
| Under the sender's capitals to the top of the subject's | 7 clear | 7 |
| Under the subject's capitals to the top of the preview's | 7 clear | 7 |
| Under the preview's capitals to the hairline below | 15 clear | 15 |
| Row to row, one line of preview | 72 | 72 (57 with none, 13 more for each further line: the system font's own line at that size) |
| Sender; subject, time and preview | 11 pt (capitals 11 tall); 8 pt (capitals 8 tall) | the same |
| Text from the list's left edge | 30 | 30 |
| Where text stops, and where the time ends, from the row's right end | 98; 24 | 98; 24 |
| Hairline | 1, `#666666`, from 2 inside the list's left edge to the rows' right end | the same (`border_strong`; `border` on a light list) |
| Right of the rows | 7 clear, a lane of 17 (`#141414`) with a handle of 9 and an arrow at each end, 5 to the list's edge | the same |
| Header | 48 high; tabs at 11 pt from 29 in, a line of 1 under the one in use on the header's last row; the arrangement at 9 pt, its arrow 11 from the rows' end | the same |
| Selected row | filled `#424242`, a line of dots (`#BDBDBD`, one on, one off) round it | `#444444` (`selection`), dots in `text_dim` |
| Unread | a bar of 4 (`#58B8FE`) down the row from 2 inside the list's edge | the same (`accent`), with the sender, subject and time in the heavier weight and the subject and time in the accent |

What differs: letters are drawn by our own rasteriser, not the system's, so strokes are a little
heavier than the target's at these sizes; the lines of a two- or three-line preview are 13 apart
by the font's own measure, which the reference (one line of preview) does not show; where marks
go when a row has several (files, importance, categories) is ours, the reference having none.

## Themes, sizes, input

- **Light, dark and follow-the-system** themes; every colour comes from `theme::Tokens`. Follow-the-system is the system's own answer on Windows, macOS and in the browser, and on Linux and the BSDs the desktop portal's `color-scheme`, followed live (#73); no portal means light.
- **Interface size** 80–200 % on top of the system scale.
- **Keyboard:** the registry's shortcuts follow the target's where it has them (Ctrl+N, Ctrl+R,
  Ctrl+Shift+R, Ctrl+F, Ctrl+Q/U, Ctrl+1–4, Ctrl+E, Ctrl+Shift+A/Q/C/K, F9, Delete, arrows).
  Missing: keytips, Customize Keyboard, full keyboard access to every control, screen-reader
  labels beyond what egui/AccessKit give by default.
- **Languages:** English, and French, German, Spanish and Italian as preview languages (named
  "Français (aperçu)", "Deutsch (Vorschau)" and so on in File › Options, every text translated, not
  yet reviewed by a native speaker; see `docs/translating.md`); Automatic follows the system. Every
  string goes through `tl!` and a pseudo-language proves it, each sentence one text with named
  places for what fills it, and a standard folder still called by its default name is shown in the
  interface language (one the owner named keeps its name), by its own word where the command of
  the same English name has another (Archive). A large ribbon button breaks its label where the
  translation does; an Options row, a reminder's Dismiss button and the all-day label make room for
  a longer translation. No right-to-left layout yet (gap #14).
- **Touch and pen:** whatever egui provides; nothing designed for them.

## Hardware and platforms

Rendering is egui on wgpu (DirectX 12 with an OpenGL fallback on Windows, Metal, Vulkan; WebGPU
with a WebGL2 fallback in the browser). Verified here: Windows 11 x64 and a Chromium browser.
High-DPI is handled by egui; a system tray and badges are absent (gap #11). Desktop alerts for
reminders and for new mail go through the system's own notifications while MailCraft runs (R7.1):
the desktop's notification service on Linux and the BSDs, toasts on Windows (for the copy the
`.msi` installed, whose Start menu shortcut names it), the notification centre for the macOS app.
A click brings the window in front and opens the message or the reminders window (on macOS it
brings MailCraft in front only). File › Options has a switch for each and says why alerts can't
be shown when they can't.
