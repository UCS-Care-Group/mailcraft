| 2026-11-22 | #1831: Own identity providers (GO1–GO10): an IMAP account signs in on its owner's own OpenID Connect or OAuth 2.0 server (Keycloak, Authentik…) in front of their own IMAP and SMTP servers. The provider's addresses are found from its issuer (OpenID Connect Discovery, RFC 8414) or typed; authorization code with PKCE S256 and a loopback redirect, an optional client secret kept in the credential store, refresh and revocation; the mail servers get the token with OAUTHBEARER (RFC 7628, new in `proto`) or XOAUTH2. Every value of a sign-in is shown in the OAuth settings and editable, Microsoft's and Google's built-in ones only by turning the account into an own-provider one. Remembered sign-ins are bound to the provider, its token address, the client and the servers; the token goes only to the account's own servers. An older MailCraft keeps such an account whole as one of a kind it doesn't know. An access token a mail server refuses during a run is renewed and the run tried once more, in the same Send/Receive.
