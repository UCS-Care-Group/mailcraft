MailCraft aims for complete parity with Microsoft Outlook, then goes further on speed, openness,
privacy and agent control. This page is the direction: where MailCraft stands, what beta must
pass and the steps to it, what comes after, and what has landed. The ranked list of shortfalls and
rough edges is [`docs/gaps.md`](docs/gaps.md). The parity checklists stay beside the two:
[`docs/parity-checklist.md`](docs/parity-checklist.md) (generated: the ribbon and menus),
[`docs/ui-parity.md`](docs/ui-parity.md), [`docs/file-format-parity.md`](docs/file-format-parity.md)
and [`docs/calendar-parity.md`](docs/calendar-parity.md).

The gap between the two readiness numbers is the story of this release: the mailbox, the
commands, the interface and the file formats are in good shape, and the connection to real mail

not yet run against any other server.

### Methodology

- **Measured.** `crates/engine/src/catalog.rs` lists 311 ribbon and menu features of Outlook by
  name, each mapped to a command id; `cargo xtask parity` counts how many of those ids the command
  registry has and writes [`docs/parity-checklist.md`](docs/parity-checklist.md). A command
  existing means the behaviour is reachable by id (ribbon, shortcut, CLI, control channel, MCP);
  it says nothing about how complete it is, which is what [`docs/gaps.md`](docs/gaps.md) and the
  other parity checklists are for. Tests are counted by `cargo xtask stats`; the 200,000-message
  figures come from `mailbox_bench`, and the progress log says how to repeat them.
- **Estimated.** "Ready for real work" weighs what a person does in a week (reading and filing
  mail, answering, scheduling, finding things) by how completely MailCraft does it, then discounts
  for what stops them getting started (connecting an account, an administrator's approval) and
  what would make them leave (losing server state, not seeing a message as sent). "Ready as a
  local viewer" weighs the same for mail exported to files (`.mbox`, `.eml`, `.ics`, `.vcf`). Both
  are the authors' judgement: no tester has reported yet. Beta is not reached by an estimate but
  by passing every item of [the beta checklist](#the-beta-checklist).

## Where it is strong

- The engine: every action a command, undoable, with a failed command leaving nothing behind and
  every command fuzzed with junk parameters.
- The readers: messages, calendars, contacts and server responses are treated as hostile and
  property-tested with arbitrary bytes.
- Privacy by default: nothing in a message runs or is fetched; passwords and sign-ins are kept only
  by the operating system's credential store, never in MailCraft's own files.
- One code base for desktop and browser.
- Agent control: CLI, control channel, MCP.

## After beta

Not scheduled; in the order of how much each matters to someone leaving classic Outlook at work,
the first people MailCraft is for. Each is a shortfall in [`docs/gaps.md`](docs/gaps.md).

1. Shared mailboxes' calendars, and delegated calendars with their permissions (gap 5, #70).
2. Bringing an Outlook archive across: `.pst` and `.msg` files (gap 12).
3. Printing messages, calendars and contacts (gap 15).
4. Warnings about a sender (failed authentication, a name that hides another address, outside the
   organisation, a link that goes somewhere other than it says) and Report Phishing (gap 17).
5. Undo Send and Delay Delivery, with an Outbox that also holds mail written offline; Snooze
   (gap 17).
6. Signed and encrypted mail with S/MIME (gap 16).
7. New mail the moment it arrives on IMAP accounts (IDLE), not at the next run (gap 2).
8. Calendars and contacts beyond Microsoft (CalDAV, CardDAV, subscribed calendars) and Google
   accounts (gaps 3, 5).
9. Microsoft To Do, with My Day and flagged mail; the organisation's directory, and LDAP, when
   addressing (gap 17).
10. Focused Inbox kept in step with Outlook; Automatic Replies; rules kept on the server (gap 17).
11. Sweep, Ignore and Clean Up Conversation, Search Folders, Quick Steps (gap 17).
12. Read receipts, one-click unsubscribe, attachments inside `winmail.dat`, Forward as Attachment
    (gap 17).
13. Free/busy across the organisation, rooms (gaps 9, 17).
14. Spell checking while writing (gap 7); native review of the French, German, Spanish and Italian
    previews, more languages, right-to-left layout (gap 14). Partly done: the four ship as previews.

## The browser build

MailCraft also builds for the browser (WebAssembly), from the same code. Every change is checked to
build, and each release carries it as a download, but it has not yet been reviewed in use, and it
can't connect to a mail server (a browser can't open the connections IMAP and SMTP need): it opens
the sample mailbox and mailboxes kept in the browser. A connection to JMAP servers, read first,
is being contributed ([#226](https://github.com/UCS-Care-Group/mailcraft/issues/226)).

It is to be a mail client of its own (decided 2026-10-19, with #226):

1. Review it: run it in the main browsers, and list what works, what doesn't and what is missing.
2. JMAP accounts: read first, then changes going up and sending (#226, being contributed).
3. Microsoft accounts through Microsoft Graph, which runs over HTTPS as JMAP does.
4. Gmail and Google Workspace accounts ([#233](https://github.com/UCS-Care-Group/mailcraft/issues/233)),
   once Google sign-in on the desktop is in ([#232](https://github.com/UCS-Care-Group/mailcraft/issues/232)).
